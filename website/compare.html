where resesh is behind

resesh is a beta. these are the gaps you are most likely to notice.

no serial, tunnels, jump hosts or ssh agent yet all four are planned, along with kerberos sign-in. if you depend on one today, securecrt, putty and mobaxterm already have it.
windows only securecrt, termius, tabby and wezterm also run on macos and linux. resesh has no plans for other platforms.
no x11 forwarding, rdp or vnc mobaxterm includes an x server, and mremoteng and mobaxterm open remote desktops. resesh is a terminal client only.
no scripting and no broadcast input, on purpose resesh leaves automation to tools such as ansible, and sends keys to one terminal at a time. if you script your client with python, securecrt is the better fit.

what the others don't do

the rows where resesh stands alone, and what each one is for.

history every command and its output, searchable other clients write a log file per session. resesh keeps each command as its own record with host, folder, time and exit result, and searches all of them at once. compare what changed since the last run put two runs of the same command side by side, with counters and timestamps ignored, so the changed line is the only thing left. rewind see the terminal as it was scrub a live session back to any moment, including full-screen programs that left nothing in the scrollback, then return to live. agents know which tab needs you tabs show which coding agent is running and whether it is working, blocked, done or failed, locally and over ssh. logins a login that belongs to the folder several clients share credentials between sessions. resesh attaches them to folders, so a new session in the folder has the right login from the start. migration your sessions come with you import ssh and telnet sessions from securecrt, putty and openssh, review them as a folder tree, and accept the shared logins resesh suggests.
