./resesh / osc

supported osc sequences

osc sequences are how a program tells the terminal something other than text: its title, its folder, a link, a status. this is what resesh understands and what it does with each one.

esc ] number ; data bel parsed by libghostty-vt works over ssh, telnet and local shells

a sequence starts with esc ] and ends with bel or esc \. the last column says what changes in a persistent session kept alive by tmux, which sits between the program and resesh. with the resesh agent nothing in this table changes, and links, prompt marks and program status come back after a reconnect.

an osc that resesh does not know is ignored and never printed. the same holds in rewind and recording playback, which also never write to the clipboard.

./try-it

try one from a shell

each line works in bash on a remote host or in a local tab.

osc 7501 report a status
$ printf '\e]7501;state=working\a' $ printf '\e]7501;state=done\a' the tab badge follows
osc 9;4 show progress
$ printf '\e]9;4;1;60\a' tab and taskbar at 60% $ printf '\e]9;4;0\a' cleared
osc 52 copy to windows
$ printf '\e]52;c;%s\a' \   "$(printf hi | base64)" "hi" is on the clipboard
osc 8 print a link
$ printf '\e]8;;https://resesh.net\a'   printf 'site\e]8;;\a\n' "site" opens resesh.net

not supported

sequences you might expect that resesh ignores today.

osc 52 clipboard read refused on purpose. a remote host should not be able to read what you copied.
osc 1337 images and the other iterm2 keys only CurrentDir is read. inline images are not drawn.
osc 633, vs code shell integration use osc 133, which resesh's own shell integration and most prompts already send.
osc 7501 child records and an alerts list only a program's root status is shown for now. the list of every tab that wants you is planned.
